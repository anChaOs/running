# 跑步视频制作工作流

这份文档只做一件事：

> 记录一条跑步视频从选题到出片，**不要忘记做的事情**。

不展开讲每一步的方法细节。
后续每个环节如果需要，可以看单独文档。

---

## 0. 这条工作流的目标

每次做视频时，只按这个顺序往下走。全长成片用 skill `p3-episode` 按需停在某一步；60–90 秒发布剪辑用剪映。

```text
选题 -> 拍摄 -> 存放素材 -> 重命名 -> 加 HUD -> 全长成片或剪映 -> 导出发布
```

---

## 1. 选题

对谈定题走 skill `p3-topic`。这一阶段把能念的口播定下来，段数跟当天的课。标题、核心观点、训练场景用几句人话交代。

### 完成标准

- 知道这条视频到底讲什么
- 知道这条视频不讲什么
- 一条视频只服务一个核心观点
- 口播是能念的分段稿

---

## 2. 拍摄

这一阶段只记住：

- 拍跑前
- 拍跑中
- 拍跑后
- 留一点 B-roll
- 尽量保留时间线线索（原始文件、手表、场景节点）

### 最低素材要求

至少有：

- 跑前 1 段
- 跑中 2~3 段
- 跑后 1 段
- B-roll 若干
- 当天 FIT 文件

### 完成标准

- 素材足够讲清楚这一个观点
- 跑中有可用口播
- 当天 FIT 文件已经拿到

---

## 3. 存放素材

视频录好以后，先不要乱放。

大素材统一放到：

```text
~/Movies/running-content/YYYY-MM-DD-topic/
```

示例（第一期曾放在）：

```text
~/Movies/running-content/2026-04-23-first-video/
```

对应仓库目录是 `episodes/2026-04-23-first-video/`。仓库里该期只保留 `assets.md` 这类轻量索引，不要把大视频原文件塞进仓库。

### 完成标准

- 原始视频已经进入素材目录
- FIT 文件已经进入素材目录
- 仓库里没有误塞大视频原文件

---

## 4. 重命名素材

存好以后，马上统一命名。

### 建议命名

```text
YYYY-MM-DD-open.mp4
YYYY-MM-DD-run-a.mp4
YYYY-MM-DD-run-b.mp4
YYYY-MM-DD-run-c.mp4
YYYY-MM-DD-close.mp4
YYYY-MM-DD-broll-01.mp4
YYYY-MM-DD-broll-02.mp4
YYYY-MM-DD-run-data.fit
```

对应到当前第一期：

```text
2026-04-23-open.mp4
2026-04-23-run-a.mp4
2026-04-23-run-b.mp4
2026-04-23-run-c.mp4
2026-04-23-close.mp4
2026-04-23-run-data.fit
```

### 重命名原则

- 尽量保留录制顺序
- 不要随便改成看不懂的名字
- 不要把原始时间线信息完全抹掉
- 视频文件和 FIT 文件放在同一个素材目录里

### 完成标准

- 所有主要视频片段命名统一
- FIT 文件命名统一
- 后面做 HUD 时，一眼知道哪个片段是哪个

---

## 5. 记录 HUD 与做封面

全长成片走 skill `p3-hud`（只记录规格进 `logs/program.json`，**不要加 `--preview`**，不在这里重压未剪原片）。透明层等时间表冻结后再用 `--prep-alpha -j 6` 与字幕校对并行渲染。封面走 `p3-cover`，与 HUD 互不依赖、可并行。

- 默认结束时间模式：`file-modified`（由 `p3-ingest` 校正 `mtime`）
- 天气用 `--weather-city shanghai`（不发 FIT GPS）；跑鞋 `-sk` 查 `training/logs/shoes.md`
- HUD 优先加在 `run-*`，不加 `open` / `close`
- 命令与参数见 `p3-hud`、`p3-cover` 与 `tools/hud/README.md`；概念与手动方案见 `knowledge/production/跑步视频HUD图层制作-概念与非脚本方案.md`

### 完成标准

- 原片时间与 FIT 对齐无误，`hud-record` 已入表
- 三比例封面（4:3 / 3:4 / 16:9）已完成

---

## 6. 预览、字幕与最终导出（或剪映短视频）

- **全长成片（主流程）**：按 `p3-episode` 顺序推进：冷开场/贴图入表 → `p3-assemble` 写 `review-preview.edl` 播放清单 → `p3-subs` 转写并冻结时间表 → 校对期间并行跑 `--prep-alpha -j 6` 与 `--measure-only` → 字幕确认后走唯一最终导出 `final_export.py --confirmed` → `p3-qc` 抽帧验收。
- **60–90 秒短视频**：走 `p3-jianying`（详见 `knowledge/production/剪映剪辑工作流.md`），主线 → 删废话 → 上 HUD（剪映需要时用 `--overlay-profile prores4444`）→ 字幕 → 导出。

---

## 7. 发布前检查与收尾

发布前至少过一遍：

- 只讲一个核心观点，开头直给，中间无废话，结尾收住
- `final-qc` 抽帧通过：HUD、贴图、接缝、烧字字幕无明显错位或重叠
- 外挂 `subtitles.srt` 与烧字成片齐备（勿在烧字成片旁留同名 `.srt`）
- 用户明确说「可以发了」后，打包 `upload/` → 自动或手动上传（`/p3-bilibili`、`/p3-youtube` Cloud Run）→ 双链齐走 `/p3-publish`（写 `published`、合 episode PR、`/p3-publish-report` 出单屏 HTML 并同步 Google Drive 复盘、列清临时清单等确认后进废纸篓）

---

## 最后固定成一个执行顺序

```text
1. 选题与可念口播（p3-library / p3-topic / p3-scaffold）
2. 拍跑前 / 跑中 / 跑后 / B-roll，高驰 MCP 拉当天 FIT
3. 收素材、统一命名并校正 mtime、锁原片↔FIT、句间刀入表（p3-ingest）
4. 记跑鞋跑完后累计里程，算出 -sn / -sk（p3-shoes）
5. 记录 HUD 规格（p3-hud --record-only）∥ 做三比例封面（p3-cover）
6. 冷开场 / 贴图入表 → 写 review-preview.edl 审片清单（p3-assemble）
7. 字幕转写与校对（p3-subs）∥ 冻结后并行画 HUD 透明层与测响度
8. 字幕人工确认 → 唯一最终导出（final_export.py --confirmed）→ 抽帧核对（p3-qc）
9. 确认「可以发了」→ 打包 upload/ → 投 B 站 / Cloud Run 传 YouTube
10. 双链齐 → published / 合 PR / 发布报告 + 复盘同步 Drive / 清临时确认（p3-publish）
11. 满 7 天：整夹搬到 Passport running-content/YYYYMM/（p3-archive）
```
