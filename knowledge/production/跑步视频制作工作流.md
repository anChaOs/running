# 跑步视频制作工作流

这份文档只做一件事：

> 记录一条跑步视频从选题到出片，**不要忘记做的事情**。

不展开讲每一步的方法细节。
后续每个环节如果需要，可以看单独文档。

---

## 0. 这条工作流的目标

每次做视频时，只按这个顺序往下走。全长成片用 skill `p3-episode` 按需停在某一步；60–90 秒发布剪辑用剪映。

```text
选题 -> 拍摄 -> 存放素材 -> 重命名 -> 加 HUD -> 全长成片或剪映 -> 导出发布
```

---

## 1. 选题

对谈定题走 skill `p3-topic`。这一阶段只确认 4 件事：

```text
标题：
核心观点：
训练场景：
这条不讲什么：
```

### 产出

至少要有：

- 一个标题
- 一个核心观点
- 一个训练场景
- 一个非目标说明

### 完成标准

- 知道这条视频到底讲什么
- 知道这条视频不讲什么
- 一条视频只服务一个核心观点

---

## 2. 拍摄

这一阶段只记住：

- 拍跑前
- 拍跑中
- 拍跑后
- 留一点 B-roll
- 尽量保留时间线线索（原始文件、手表、场景节点）

### 最低素材要求

至少有：

- 跑前 1 段
- 跑中 2~3 段
- 跑后 1 段
- B-roll 若干
- 当天 FIT 文件

### 完成标准

- 素材足够讲清楚这一个观点
- 跑中有可用口播
- 当天 FIT 文件已经拿到

---

## 3. 存放素材

视频录好以后，先不要乱放。

大素材统一放到：

```text
~/Movies/running-content/YYYY-MM-DD-topic/
```

示例（第一期曾放在）：

```text
~/Movies/running-content/2026-04-23-first-video/
```

对应仓库目录是 `episodes/2026-04-23-first-video/`。仓库里该期只保留 `assets.md` 这类轻量索引，不要把大视频原文件塞进仓库。

### 完成标准

- 原始视频已经进入素材目录
- FIT 文件已经进入素材目录
- 仓库里没有误塞大视频原文件

---

## 4. 重命名素材

存好以后，马上统一命名。

### 建议命名

```text
YYYY-MM-DD-open.mp4
YYYY-MM-DD-run-a.mp4
YYYY-MM-DD-run-b.mp4
YYYY-MM-DD-run-c.mp4
YYYY-MM-DD-close.mp4
YYYY-MM-DD-broll-01.mp4
YYYY-MM-DD-broll-02.mp4
YYYY-MM-DD-run-data.fit
```

对应到当前第一期：

```text
2026-04-23-open.mp4
2026-04-23-run-a.mp4
2026-04-23-run-b.mp4
2026-04-23-run-c.mp4
2026-04-23-close.mp4
2026-04-23-run-data.fit
```

### 重命名原则

- 尽量保留录制顺序
- 不要随便改成看不懂的名字
- 不要把原始时间线信息完全抹掉
- 视频文件和 FIT 文件放在同一个素材目录里

### 完成标准

- 所有主要视频片段命名统一
- FIT 文件命名统一
- 后面做 HUD 时，一眼知道哪个片段是哪个

---

## 5. 加 HUD

这一阶段只做这几件事：

1. 检查视频时间
2. 先 dry run
3. 正式生成 HUD 文件
4. 检查 HUD 是否明显错位

### 当前 HUD 流程

先检查时间：

```bash
.venv/bin/python tools/hud/probe_video_times.py <mp4文件>
```

再 dry run：

```bash
.venv/bin/python tools/hud/render_running_hud.py --media-dir <素材目录> --overlay-only --preview --dry-run
```

再正式生成透明 HUD，并按原片同档烤一版可看的预览：

```bash
.venv/bin/python tools/hud/render_running_hud.py --media-dir <素材目录> --overlay-only --preview
```

若这条只要全长成片（拼接、转场、字幕、封面，不进剪映），从 skill `p3-episode` 往下走需要的阶段。60–90 秒发布剪辑仍用剪映（`p3-jianying`）。

输出是 `hud-renders/*-hud-alpha.mov`（透明层）和 `*-hud-preview.mp4`（跟原片同编码、同码率）。当前默认的结束时间模式建议用脚本默认值即可，也就是 `file-modified`。天气用 `--weather-city shanghai`；明确不要天气时加 `--no-weather`。不要把 FIT GPS 发给 Open-Meteo。跑鞋 `-sk` 查 `training/logs/shoes.md`。

### 当前 HUD 主要加在哪些素材

优先：

- `run-a`
- `run-b`
- `run-c`

一般不优先：

- `open`
- `close`

### 完成标准

- HUD 文件已生成
- 时间线没有明显错位
- 位置没有明显挡住主体

HUD 的详细说明另看：

- `knowledge/production/跑步视频HUD图层制作-概念与非脚本方案.md`
- `tools/hud/README.md`

---

## 6. 剪映剪辑

这一阶段只记住：

- 先排主线
- 再删废话
- 再上 HUD
- 再补字幕和包装
- 最后导出

剪映的详细流程单独看：

- `knowledge/production/剪映剪辑工作流.md`

### 完成标准

- 主线顺
- 节奏顺
- HUD 和字幕不打架
- 能导出发布版

---

## 7. 导出发布前检查

发布前至少过一遍：

- 这条视频是不是只讲了一个核心观点
- 开头能不能快速让人知道要讲什么
- 中间有没有废话
- HUD 有没有明显错位
- 全长成片字幕默认外挂（B 站和 YouTube 都传 SRT），成片里不应烧字
- 外挂字幕有没有压 HUD（两边网页播放器开 CC 看；SRT 贴底栏）
- 结尾有没有收住

---

## 最后固定成一个执行顺序

以后每次都按这个顺序走：

```text
1. 定标题、核心观点、训练场景、非目标
2. 拍跑前 / 跑中 / 跑后 / B-roll
3. 把原始视频和 FIT 放进 ~/Movies/running-content/YYYY-MM-DD-topic/
4. 统一重命名素材（校正 mtime）
5. 记下跑鞋跑完后累计里程
6. 检查视频时间，生成 HUD
7. 全长成片：字幕 / 封面 / 拼接 / 核对
   或剪映：排主线、叠 HUD alpha、字幕、导出
8. 发布
```
