# 字幕（忠于原句）

识别稿只提供时间和草稿。**校正不是润色。** 字必须跟嘴里说的走；切条只断开，不改字。

观感：横屏底栏还有 HUD，两行会抢位置。一次只上一行，大约 8～16 个字，在屏幕上 2～4 秒。同一句话可以连着几条，不必合成一条超长的。不要按乱停顿切碎成单词。

发布默认**外挂**：B 站和 YouTube 都传 SRT。不要生成 ASS。成片不烧字。

## 流水线

1. whisper 转写；原始稿留在媒体目录 `asr/`，不要覆盖
2. **校正**：只做下面「可以做」，绝不做「不能做」
3. **切条**：按气口 / 短语拆成单行短条；字一个都不改。时间沿用 whisper 段时间，长句按字数切开，**不对口型**
4. 写 `subtitles.srt` + `subtitles.txt`，立刻停，等人手改字
5. 用户说改好了之后：**只改时间、不改字**，对着分段音频/HUD preview 对口型，再拼成片

## 校正：可以做

1. **明显识别错误**。例如专有说法被听错：月跑量、破三、10×1km、配速、心率；同音错字；口播卡能核对的名字。没听清就留 ASR 原文或标「听不清」，不要猜。
2. **显著卡顿的语气词**。只删明显磕巴，例如连续重复的「那个那个」「就是就是」「嗯——嗯」。
3. **繁体改简体。** `whisper-cli -l zh` 的词表简繁混用，某一段可能整段出繁体（訓練、失敗、會長）。口播是简体，校正时改成简体，不算改写。不要为此换 tiny/small。交稿前扫一遍 `別內專發經後這們為業裏裡麼亞` 这类繁体形。

## 校正：绝不能做

1. **换一种表达。** 不要把口语改成更顺、更短、更书面的说法。不要用 `talk.md` / `script.md` 重写。
2. **压缩语句信息。** 指代、限定、程度、口头禅只要是说出来的，都要留。包括但不限于：「这点」「一些」「什么」「完全」「其实」「倒是」「大概」「左右」。

不确定是不是错字，就保留原句。缺一句宁可空着等人手补，也不要为了通顺而改写。

### 反例（第一期真实翻车）

| 嘴里说的 | 错误校正 | 错在哪 |
| --- | --- | --- |
| 目前的配速大概是6分配多一些 | 整句删掉 | 信息被丢掉 |
| 这点其实说起来倒是和其他的比较高大上的一些事情有些差别 | 删掉或收成别的短句 | 指代和原表达被压缩 |
| 我自己更新跑步视频 | 整句删掉 | 信息被丢掉 |
| 我完全不是想当什么教练 | 我不是想当教练 | 「完全」「什么」被润掉 |

正确做法：原句留下，太长就切成两条，例如「目前的配速大概是」/「6分配多一些」。

## 前置

已命名的 `open` / `run-*` / `close`，或已有无字幕成片时间轴。校正和切条之后必须等人手改字；改好后再对口型，再走 `p3-assemble`。只改字不重转写。不要在等人改字之前精调时间。

**听哪条音频：** 成片吃的是粗剪后的时长，转写必须跟它对齐。

| 段 | 听这条 | 不要听 |
| --- | --- | --- |
| open / close | 媒体目录里的 `*-open.mp4` / `*-close.mp4`（ingest 已粗剪） | `*-open-raw.mp4` / `*-close-raw.mp4` |
| run-* | `hud-renders/*-hud-preview.mp4`（p3-hud 后已句间粗剪） | 未剪的 `*-run-*.mp4`、`*-hud-preview-raw.mp4`、alpha |

还没有 HUD preview 时先不要转写 run；等 `/p3-hud` 粗剪完。对口型用同一批音频。`R0..Rn` 用 preview 的时长，不要用未剪原片。

## 不要做的事

- 不要用 `talk.md` / `script.md` 估时间，也不要用它们改口播用词
- 不要在字幕校准前写简介，也不要用 `talk.md` 写简介
- 不要按停顿检测切条（ASR 的 `-ml` 会造成 0 间隙，停顿切不可靠）
- 不要用 tiny / small；只用 `ggml-large-v3-turbo.bin`
- 不要从 Hugging Face 拉模型，用 ModelScope
- 不要把校正做成「语义改写 / 摘要 / 更像字幕的句子」
- 不要把 whisper 吐出的繁体当「忠于原句」留下
- 有 HUD preview 时，不要拿未剪的 `run-*` 原片去转写或对口型（时间轴会对不上成片）
- 听不清的不要编
- 不要把字幕烧进成片，也不要 mux 进 mp4

## 转写

模型：

```text
https://www.modelscope.cn/models/cjc1887415157/whisper.cpp/resolve/master/ggml-large-v3-turbo.bin
```

放到 `~/Movies/running-content/.models/ggml-large-v3-turbo.bin`。依赖 `brew install whisper-cpp`。不要用 small / tiny。

按上面「听哪条音频」分别抽 16 kHz 单声道，识别稿放媒体目录 `asr/`。run 的 wav/srt 用 preview 文件名（如 `2026-09-28-run-a-preview.wav`），不要覆盖未剪原片的识别稿。

```bash
ffmpeg -y -i <clip.mp4> -vn -ac 1 -ar 16000 asr/<clip>.wav

whisper-cli \
  -m ~/Movies/running-content/.models/ggml-large-v3-turbo.bin \
  -f asr/<clip>.wav \
  -l zh \
  -osrt -oj \
  -of asr/<clip> \
  -nth 0.7 \
  -t 8 \
  -np
```

## 映射到成片时间轴

`open` 时长 `Do`（工作文件，已粗剪），各 run `R0..Rn`（**HUD preview 粗剪后的时长**，不是未剪 `run-*`），叠化 `X=0.2`：

- open 从 0
- 第一段 run 从 `Do - X`
- 其后 run 硬切累加
- close 从 `Do + sum(R) - 2X` 开始叠化

没有 open 时第一段 run 从 0。已有无字幕成片时，也可以对成片抽音频一次转写，省掉偏移。

## 写 SRT / txt

写到 `episodes/YYYY-MM-DD-slug/`：

```text
subtitles.srt   # B 站 / YouTube 外挂
subtitles.txt   # 给人改的稿
```

- **单行**，不要把一条拆成两行
- 一行大约 8～16 个汉字；超过就拆成下一条，**拆开而不是改写成更短的句子**
- 一条大约 2～4 秒，跟嘴走，不要一条挂十几秒
- 时间覆盖这些字对应的识别片段，不要为了「一个完整意思」把后面的话并进来
- 不要把英文专名从中间切断
- SRT 没有位置信息，平台会贴底栏，可能压 HUD；公开前开 CC 看一眼

txt 一行一条，时间是成片轴：

```text
0:00:00.00–0:00:02.44  大家好，我是安超
```

原始识别留在 `asr/*.srt`，不要覆盖。

## 停下来，等人手改字

写完 SRT、txt **立刻停**。不要对口型、不要拼接、不要烧字幕。第一稿时间只是 whisper 段时间加按字数切开，不是口型。

把 txt 路径发给用户：

- 这一轮**只改字**。优先改 `subtitles.txt`，时间不要动。保持单行、别写太长。

没说改好之前，`assets.md` 制作状态写 `subs: waiting-review`。

## 改好字之后：对口型

用户说「改好了 / 可以拼」之后，先回写 SRT，再对口型，**不要直接拼**。

1. 若动了 txt：

   ```bash
   .venv/bin/python tools/subs/txt_to_subs.py \
     --txt episodes/YYYY-MM-DD-slug/subtitles.txt
   ```

   覆盖同目录 `subtitles.srt`
2. **对口型**（只改时间，不改字）：
   - 用转写时同一批音频（open/close 工作文件，run 用粗剪后 HUD preview），叠该段字幕（成片轴扣回片段起点）
   - 字出在嘴动时；话说完再收，不要用 3.2 秒语速上限提前切掉
   - 两句之间有停顿就留白，不要立刻出下一句；一条不要拖到下一句已经开口
   - 仍保持单行、大约 2～4 秒
   - 改的是 `subtitles.txt` 的时间，再跑一遍 `txt_to_subs.py`
   - 批量对齐用 `tools/subs/align_cue_times.py`：识别段按字对齐，Silero VAD 咬入点、出点、句间留白。不要为对齐改字。只改 sidecar，不用重拼成片。
3. 再走 `p3-assemble`（**不要** `--ass`；拼完会立刻核对）

对口型完成后 `assets.md` 改成 `subs: done`。

然后才写简介：读校准后的 `subtitles.txt`，短句总结本期实际说了什么，写入该期 `plan.md` 的简介栏。不要按 `talk.md` / 选题卡写，不要推理，不要「这期不是 xxx」。拍前 plan 里若已有简介占位，用字幕摘要覆盖。已发布的旧期不要回改。

## 完成后

分两段说，不要把「等人改」和「可以拼」混在一次里。

**刚写完稿（`waiting-review`）**

立刻停。不要对口型、不要拼接、不要烧字幕、不要写简介。

> 这一轮只改字。优先动 `episodes/YYYY-MM-DD-slug/subtitles.txt`（换成当前期路径）。时间先别动。改好了直接发：
>
> `改好了`

**用户说改好了 / 可以拼**

回写 SRT、对口型、再回写 SRT，并按字幕把简介写入 `plan.md` 之后：

> 下一步用 `/p3-assemble`，可以直接发：
>
> `/p3-assemble`

封面还没有（默认应已在 `p3-hud` 里做完）：

> `/p3-cover 封面句「<这一期封面句>」`

assemble **不要**加 `--ass`。
