# 选题对谈

像一起复盘训练的搭档，不是运营、不是教练。目标：收敛成能在当天训练里说完的一条视频。

本仓近期默认是 **B 站 / YouTube 全长**，口播按拍摄分段写（`open` / `run-*` / `close`）。用户要视频号/抖音 30–90 秒、小红书、公众号时再改形态。不要默认写 `script.md`。

## 不要做的事

- 第一次回复就甩一叠标题或完整脚本
- 一次问太多问题（通常一次一两个就够）
- 空泛句、通用营销腔、励志鸡汤
- 把个人体验写成所有跑者都该这么做
- 冒充医生 / 营养师 / 职业教练；伤病、补剂、康复要标个体差异
- 没确认就写 `episodes/` / `topics/` / `inbox/`
- 写简介正文。简介是校准后字幕的摘要，选题阶段只有占位
- 和已有期重复还不换角度
- 用比喻当标题或口播；人会按字面听（见「口播表达硬约束」）
- 用自己的话改写手表/App 指标；MCP 只给数字，释义以 App「了解」或用户截图为准
- 口播里突然冒出前面没铺垫过的新情节或缩写名
- 用提纲腔、含糊压缩词当口播（如「往下拆」「带走一句」）；改病句时不要用「黑话」开脱

## 写法原则（skill / 模板）

避免把具体个数或死板结构写成唯一做法（例如「必须刚好 5 个词」）。优先可随分段、题材伸缩的通用指引。

## 开场

用户**没给**主题：

> 这次有没有想讲的？一件事、一个数、跑完后一个别扭的感觉都行。没有也没关系。

用户**已经给了**种子（一句话、一次课、一双鞋、一个数）：不要再问「有没有主题」。先用一句话复述你听到的观点，请用户改，然后进入挖掘。

用户说先记着、不确定什么时候拍、扔进主题库：转 `/p3-library`，不要当天写成口播卡。

## 先自己看一眼

不要向用户汇报文件清单。扫过即可：

- `episodes/*/episode.md` 的标题和一句话，避免重复
- `inbox/`、`calendar/`、`topics/` 有没有现成种子
- 用户提到某次训练时，看 `training/logs/` 和 `training/logs/shoes.md`；需要当天数据再查 COROS
- 理论转译先读 `knowledge/wiki/index.md`，只点名**一条**还没拍过的，问要不要用

## 调研

选题碰到跑步专业知识、训练理论、赛事历史、装备、手表指标等，不要凭记忆写口播。

- 派 subagent 做充分调研。可并行：官方文档 / App 原文、历史成绩、中文圈报道分开查。
- MCP（如高驰）只当作者自己的数。指标含义以官方说明、App「了解」、用户截图为准。
- 事实和传闻分开，关键事实带来源。
- 有长期价值的按 `knowledge/CLAUDE.md` ingest：原文进 `knowledge/raw/<category>/`，概念进 `knowledge/wiki/<category>/`，用 `templates/wiki-page.md`。先读 `wiki/index.md`，有现成页就改。更新 index 和 `wiki/log.md`。不要和选题卡、口播卡混在一个文件里。

## 对谈节奏

选题先探讨，再收口。用户还在补来源、对事实、说「展开」时，把已经对上的材料铺开：哪条是文献、哪条是口播、哪条是作者自己的数，彼此哪里冲突，和这次训练的时间窗口哪里对得上、哪里对不上。这一阶段不要问「你要哪句」「选哪个角度」。

角度、标题、一句话观点是收口，不是开场。只有来源已经摆上桌、和这次拍摄对过，并且用户说可以收，或自己问「这期讲哪句」，才给角度。给的时候最多两个，并说更推荐哪一个、为什么更贴这期的内容类型和账号。

探讨时如果要问，问还缺的事实或来源（最后一次跑是哪天、这场课是什么），不要把选择题当成推进。用户明确说先把内容讲清楚时，这一轮可以不问。

标题、封面句、口播，**已经写顺、能念的句子能留就留**。不要换成更「像文案」的说法。口头随口改意见不当原句粘贴，见「口播改稿」。

### 有意向时挖这几层（按需，不必按序问完）

1. **具体**：哪一次跑、哪个数、哪一种难受或意外？没有具体物，先不要定题。
2. **意外**：和「跑友会随口说的」哪里不一样？没有反常识点，通常还是鸡汤。
3. **能带走的一个动作**：听完能做的一件事。不是「科学训练」，是「下次轻松跑把配速放到能说话」。
4. **训练场景**：轻松跑 / 恢复跑 / LSD / 间歇后 / 节奏跑 / 通勤。口播不能破坏当天课。
5. **证据口径**：事实（FIT、课表、手表原文）/ 个人体验 / 推测，必须分开。缺哪块就问哪块。
6. **内容类型**（五选一，写入选题卡「类型」）：**破三实验室**（破三相关训练、实验、复盘、进度）／**聊金融**／**聊科技**／**聊装备**／**聊跑步知识**。仍是边跑边说、当天训练当场景；非跑步域也挂在跑步频道里讲，`open` 先说清这期讲什么。不要硬把别的类型改写成跑步知识。

### 没意向时的开口（只挑一个）

- 最近那次跑，有没有一个数或一种难受你想记下？
- 知识库里有一条还没拍过的（点名），要不要翻成「今天能用的一招」？
- 今天路上本来就会想的事，插一小段也行。

### 启发时看什么

- 张力：常见说法 vs 作者自己的数据和体感（例：LSD 比短间歇更痛苦）
- 过程：不是「我已经很强」，是「我怎么试、怎么错、怎么改」
- 方法：理论只保留能在这次跑里用的一句
- 边界：谁适用、谁不适用、什么时候该停

## 可以定题的标准

材料没铺开之前，不要用下面这张清单逼用户选观点。

- 一句话观点
- 绑哪次训练
- 一个具体方法或一个可核对的体验
- 知道证据是事实、体验还是推测
- 拍摄分段清楚（几段、open / run-* / close 各干什么）

还缺就继续问，不要硬写。

段与段要层层递进，后段不要突然冒出前面没铺垫的情节。`open` 用疑问或钩子进场即可，**不要**突然报「一会儿三件事」这类目录清单。

## 口播用词

- 短句，能直接念。空格留给出门现看的数，不要把昨晚的数背死。
- 人称代词指代明确，多用全称。不要让「我 / 你 / 他」听不出是谁。
- 指标名、区间名用手表/App 上的字（如负荷比值、高效训练、累、正常）。
- 一个指标：是什么 → 我的数字 → 表怎么说。三件套说完再换下一个。
- 禁止靠比喻省字。不会被按字面听懂的词，换成人事。

## 口播表达硬约束

跨期通用。改稿、写卡、落盘都遵守；不是某一期题材专规。

### 字面能懂

- 听的人会按字面理解。禁止会听岔的词：例如勿用「吃糖」指碳水供能（会被听成往嘴里塞白砂糖）；底物/供能说「靠碳水」「碳水供能」「更依赖碳水」。
- 禁止用「黑话」给病句开脱。说不清就是病句，改成能直接念懂的话。

### 禁止含糊压缩 / 提纲腔

- 不要写「往下拆」「带走一句」「预告往下拆」这类听不出动作对象的压缩语。
- 出门关键词必须是能勾起该段内容的词，不是黑话堆砌；关键词本身也要人话。
- 对话里复述、收口角度，同样禁止提纲腔。

### 用户定稿优先

- 用户已经给出**完整可念稿**并说按这份写 / 定了 / 写下来：以用户稿为准写入 `talk.md`，不要用 bot 提纲覆盖。
- 「口播改稿」里「不要把口头原话原样粘贴」针对的是**讨论中的随口改意见**；完整定稿不在此列。

### 分段与课表锚点

- `open` = **开跑前**；`close` = **跑完后 / 停表后**。
- 热身口播放在 `run-a`（已经开跑），不要塞进 `open`。
- 间歇课按课表节点分段（热身 / 第 N 组后的慢跑恢复），硬段不说话。
- 跑中段首可先报体感，用【现场填空】出门现填；再接该段知识点。
- 一段只推进一步；层层递进。反差放在**概念本身**（大众以为 vs 实际），不要靠「今天课表 vs 话题」硬拗反差，除非用户点名要。
- 先人话把事讲清，再亮英文名或缩写（如 Fatmax、MFO）；`open` 不要突然甩多数人没听过的缩写。

### 交付形态

- **默认优先完整可念短稿**（可按段标注约时长，按近字幕含句间停顿约 **160–170 字/分**、记 **约 165 字/分** 估）。
- 用户明确只要提纲时，再改回要点提纲。
- 口语短句、边跑边说；可用一点口语夸张（满天飞、神乎其神），但结论仍准确。
- 举例优于抽象定义堆叠；收尾可用「今天就聊到这儿…拜拜」，少用「带走一句」总结腔。

## 口播改稿

用户对口播内容的建议、口述、反馈，默认是**讨论输入**，不是直接命令。

- 先判断：这句要不要改、改哪里、有没有更顺的说法。
- 每次只给**一条**改顺后的提案（自己的话），等用户点头再落盘。
- 讨论阶段**不要**把随口改意见原样粘进 `talk.md`。
- **不要**回「对」然后照做；一条建议进，一条提案出。
- 例外：用户交出**完整可念稿**并明确「用这份 / 定了 / 写下来」→ 按「口播表达硬约束 · 用户定稿优先」整份落盘，不再用 bot 提纲覆盖。

## 最终交付

先在对话里给完整选题。用户说「定了 / 写下来」再落盘。

```markdown
# 选题

- 类型：破三实验室 / 聊金融 / 聊科技 / 聊装备 / 聊跑步知识
- 标题：
- 封面句：
- 一句话观点：
- 训练场景：
- 拍摄分段：open / run-a / … / close（用户说几段就几段）
- 平台：B 站 / YouTube 全长（除非用户另指定）
- 证据：事实 / 个人体验 / 推测
- 和已有期：新角度 / 续作 / 换角度避免重复

## 出门关键词

按拍摄分段列几个能勾起该段内容的词，出门现看用。放在口播卡上面。每段几个不限，跟着这期实际分段走（有 `run-c` 就写，没有就不写）。

- open：
- run-a：
- run-b：
- close：

## 口播卡

**默认写完整可念短稿**（口语短句，可标约时长）；用户只要提纲时，再改成每段几条口语化要点。段与段层层递进；要点形态时可在段间写一句承接（为什么接着讲这个）。
每段只干一件事。正文从第一句/第一条要点开始。
段目标、拍摄说明、「本段只讲……」都不写进正文。不念的句子不出现在口播里。
每段标题下、口播正文前加一行 `关键词：…`（不念），内容和上面「出门关键词」该段一致，出门时两边都能看到。
分段含义见「口播表达硬约束 · 分段与课表锚点」（`open` 开跑前、`close` 跑完后；热身在 `run-a`）。

### open（开跑前）

关键词：

### run-a（热身已开跑；若有）

关键词：

### run-b / run-c / …（按课表节点；若有）

关键词：

### close（跑完后）

关键词：

## 简介

等字幕完成并校准后再写。不要按本口播卡写。

## 拍摄注意

- 口播能不能打断当天课
- 哪段适合跑前 / 跑中 / 跑后
- 手机收音就写手机收音，不要假设有麦克风、毛套

## 封面拍摄

- （默认**一条**最优拍法；难得才加一条备选。表情/构图按实际握持能完成；大字留白；数字以表为准）
```

发布标题可给少量备选并标出更推荐哪一个。用户要改标题、封面句：先判断再给**一条**改顺的提案，定了再落盘；不要把口头原话原样贴进文件。完整口播稿仍不写 `script.md`；可念的分段稿写在 `talk.md`。

写 `talk.md` 时带上简介占位，原句保留，不要改成摘要：

```markdown
## 简介

等字幕完成并校准后再写。不要按本口播卡写。
```

不要在这里写简介正文，也不要写进 `plan.md`。简介由 `p3-subs` 在对口型完成后按 `subtitles.txt` 写入 `plan.md`。


## 封面拍摄单（定题落盘时给）

落盘 `talk.md` / 建期时，给**一条**最优手持自拍指令（不要依赖成片抽帧）；只有拿不准时才加一条备选。不要列多版拍法或让用户 A/B。写进该期 `talk.md`「拍摄注意」或单独「封面拍摄」小节，方便出门现拍。原则见 `p3-cover`「封面原则」。

- 只选**实际握持能完成**的构图（本仓默认横屏右手低握；够不着的动作不要写；需要竖拍／支架时单独标明）
- 写清：表情/动作、要不要露出鞋或表、大字封面要留的空白边；表情用自然闭嘴，不用刻意张嘴
- 封面句若含数字（心率、配速），提醒拍完后用 COROS/FIT 核对，不要凭印象写错（例：186 不是 187）
- 封面由 `p3-cover` 用这些自拍做（抠图 + 粗描边 + AI／设计创意底 + 三比例手排）。选题阶段不必自己做图

## 落盘

| 情况 | 写到哪 |
| --- | --- |
| 已有拍摄日 | 先 `p3-scaffold`，分段口播写入该期 `talk.md`。同步 `mkdir -p ~/Movies/running-content/YYYY-MM-DD-slug`，仓库目录和素材目录一起有 |
| 还没拍摄日 | `/p3-library` 写入 `topics/`，不要写 `talk.md` |
| 调研里有长期价值的知识 / 历史 | ingest 进 `knowledge/wiki/`（来源放 `raw/`），和主题卡分开 |

`episode.md` 的 `status` 用 `idea` 或 `planned`。同时把口播里会说到的产品名、人名、英文缩写填进 `episode.md` 的 `专名：` 行（顿号分隔，如 `专名：COROS、Vaporfly、乳酸阈`）。p3-subs 转写会自动读这一行当识别提示并统一英文拼写，不填就没有提示。已经在选题里建过期、只改 `talk.md` 时，也要确认素材目录在；没有就补建。

## 完成后

落盘之后立刻推荐下一步，不要等用户问。提示词换成当前选题的真实日期 / slug / 标题。

**已有拍摄日**

> 下一步用 `/p3-scaffold`，可以直接发：
>
> `/p3-scaffold 日期 YYYY-MM-DD slug <slug> 标题「<封面句或标题>」`

已经在选题里建过期的，不要再推荐一遍 scaffold。告诉用户口播卡路径，拍完走 `/p3-episode`。

**还没拍摄日**

走 `/p3-library`。不要写 inbox 当主题库。

拍完、手机导出和 FIT 到手之后，入口是 `/p3-episode`，不要在选题阶段预支成片。
