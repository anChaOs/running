### open｜开跑前（约 1 分 40 秒）

关键词：做不完、片太长、停顿长、今天聊怎么改

哈喽大家好，我是安超。今天是 11 月 4 号，星期三，出门跑一段轻松有氧。

最近做跑步视频，有两件事特别烦。一是早上跑完到出门上班，成片流程经常走不完，机器还在压画面，人已经要走了。二是片子本身偏长，停顿拖沓，听着就坠。

所以我想优化这条剪辑管线。今天不聊哪家模型更强，就聊我怎么带着 AI 改自己的工作流，以及 Anthropic 审代码的做法，我能不能借鉴。

准备就绪，出发。

### run-a｜开跑后（约 2 分 20 秒）

关键词：审 skill 和代码、挖不合理、别扭变议题

刚跑起来，先说怎么提出优化。

我不是一上来就说「帮我优化 skill」。是先抓住用的时候的别扭：为什么响度、烧字好像又把整段画面重压一遍？为什么冷开场接上之后又消失了？为什么 skill 里写的切条规则和脚本对不上？

我会让 AI 先 review skill、再看代码，用它能讲清楚的话，把剪辑链路讲一遍：哪一步在重编码、哪几处文档在复述同一套规则、哪里原则打架。

然后再让它找 pipeline 不合理的地方。关键是把别扭收成议题——真源应该在哪、谁负责改、改完怎么证明没弄坏别的——而不是丢一句「整体优化一下」。

### run-b｜中段（约 2 分 30 秒）

关键词：A/B、埋点、timeline、人定序 AI 动手

有了议题，怎么落地？

人定方向：总序是什么、哪些原则不能破、哪个 PR 先开着不合。AI 去做盘点、改代码、写测试、开 PR、跑实验。

改完要对照。我会做改前改后的 A/B：墙钟花了多久、成片是不是更短、失败点有没有归零。没有数，就容易变成「感觉好一点」。

再往前留一步：pipeline 里埋点。每期把各步耗时和失败写进日志，下一刀优化才知道慢在 HUD 还是烧字，不用靠印象。

一句话：AI 是手脚和显微镜，业主和质检还是我。

### run-c｜后段（提纲，出门展开）

关键词：Anthropic 审 PR、分层、验证、收敛、能抄什么

再说 Anthropic 怎么审代码。我的工作流也在往自动化靠，先看他们怎么做，再想能抄什么。

提纲（出门现展开）：

- 目标：少占人的时间，revert / 事故别涨
- 审查贯穿全程，不是最后一道人肉闸
- PR 前：能跑就先跑（测试、构建、截图）；子 agent 换新上下文再看；内部 skill 找 bug / 简化
- 每个 PR：AI 先审；多 agent 找问题 → 投票降误报 → 按严重度挂评论
- 安全审查：不过就不能合
- CI：lint / 类型 / 测试 / 构建照样挡
- 人按风险进场：低风险可无人；普通一人；高风险两人；agent 批准不算人
- 合入后：合并队列、功能旗、灰度；出事快撤
- 审查要收敛：轮次帽，别 agent 互修几十轮
- 人还盯：做不做、高风险、定调架构、读证据、you land it you own it
- 注意：文里「日均三万」是大 monorepo，不是 Claude Code 自己的仓
- 我能抄：分层检查、先验证、要收敛、默认写回文档；不抄他们无限 Token 的堆法


### close｜停表后（约 3 分 10 秒）

关键词：人干什么、Anthropic 怎么说、Token 越多越强吗、拜拜

收两个思考。

第一，AI Loop 里人究竟扮演什么？Anthropic 那篇讲 code review 的文章，写得很清楚：机器可以读大多数 diff，人仍要守几件事——决不决定做、品味和范围；盯高风险代码，比如计费、自动更新、CI 工作流；审会定调的架构；还要读证据，测试输出、命令结果、截图、审查发现，说不清检查会漏什么，就别随手批准。而且你落地的改动，你还是 owner，agent 写的也算你的。

对照我自己的剪辑管线，也是同一套：总序和原则我定，合不合、清不清我点头，AI 负责盘点、改码、跑实验。

第二，Token 越多越强吗？我个人用 AI，Token 从来不是无穷的，所以我会想办法少浪费——少空转、少重复喂上下文、能验证了再往下走。

可 Anthropic 那套 review，几乎是 Token Max：多轮审查、层层筛选，几乎每轮都有 agent，还经常是多 agent。一个 PR 也许就改了几百行，写代码本身未必费多少 Token；后面 review、拦截、各种消息来回，消耗可能是写作本身的很多倍。

他们公认很强，产品也硬；事实是，他们几乎像有无限 Token，能堆出这种近乎完美的工作流。普通人没有这本钱去原样复制。所以我才问：是不是 Token 越多就越强？强，有多少是堆出来的？我们普通人，又该把有限的额度花在哪一刀最值？

今天就聊到这儿。我是安超，我们下期见，拜拜。
