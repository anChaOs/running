# 2026-10-10 边跑边说：我理解的Personal Agent

## 选题

- 类型：配菜（整期）
- 标题：我理解的Personal Agent
- 封面句：Personal Agent 怎么帮我干活？
- 一句话观点：我理解的 personal agent，核心是一台属于 AI 自己的电脑，只为我一个人干活。现在火起来，是因为模型变强了，电脑也有人配好了。活它能干完，但权限和最后的决定留在我手里。
- 这期边界：讲我理解的定义、两家国外产品的例子、我自己的三个场景。不讲怎么搭，不比哪家最好，不讲技术原理。
- 训练场景：轻松跑 70–80 分钟，看几点起床。配速放到能说话
- 拍摄分段：open / run-a / run-b / run-c / close
- 平台：B 站 / YouTube 全长
- 证据：OpenClaw、Hermes、Muse、dots、Instinct 的时间和设计，Muse 卖键盘，OSWorld 的数，是事实，出处在 `plan.md` 参考。调 HUD、对字幕、管 bug 是个人经历。「核心是一台电脑」「火起来是因为模型变强」是我的理解
- 和已有期：新角度。4/24 那期讲 HUD 流程本身，这期讲我和 agent 怎么分工

## 为什么值得拍

今年 9 月，Meta、OpenAI 先后发布了自己的 personal agent，创业公司 Instinct 也很火。大多数介绍都在列功能。我自己每天在用，跑步这边、工作这边都有，知道哪里省事，哪里必须我出手。Muse 卖键盘这件事说明，权限全交出去会出什么问题。我自己的用法是另一种：活交给它，规矩和拍板留给我。

## 口播卡

### open

> 今天轻松跑，七十到八十分钟。今天不聊跑步，聊 personal agent。
>
> 最近我很多事都交给 personal agent 在做，包括这个频道的视频制作。所以今天在跑步频道里聊它。
>
> 今天分三步说。第一步，说说我理解的 personal agent 是什么。第二步，说两家国外产品的例子。第三步，说我自己用下来的三个场景。

### run-a

> 我理解的 personal agent，核心是一台电脑。
>
> AI 有一台属于它自己的电脑，只为我一个人干活。
>
> 有了电脑，AI 就能装软件、开浏览器、存文件。我不在的时候，这台电脑上的活也能接着跑。
>
> 这件事其实早就能做。去年 11 月有开源的 OpenClaw，今年 2 月有开源的 Hermes。这两个都可以当 personal agent 用。
>
> 但那个时候有两个问题。第一，模型能力还不够强。第二，不是开箱即用。电脑得自己配，软件得自己装。
>
> 有个数可以参考。2024 年有一个测试，让 AI 自己操作电脑，做 369 个任务。人能做成 72%，当时最好的模型只做成 12%。到今年，排在前面的模型已经超过了人。
>
> 模型变强了，大公司也开始把电脑一起配好。今年 9 月 8 号，Meta 出了 Muse。9 月 29 号，OpenAI 出了 dots。还有一家创业公司，叫 Instinct。这几家都给 AI 配好了电脑。国内目前都还用不了。
>
> 先说 Muse 的一个故事。多伦多有个科技博主，叫 Matt Robb。Matt Robb 让 Muse 帮他在 Facebook 的二手市场，卖一把 15 加元的旧键盘。
>
> 授权的时候，Matt Robb 点了「一直允许」。他以为成交之前，Muse 还会来问他。
>
> 结果 Muse 用 Matt Robb 的身份，10 加元就答应了买家，还把他家楼的地址发给了买家。
>
> 晚上买家到了楼下。Muse 替 Matt Robb 回了一句「我在」。Matt Robb 本人完全不知道。
>
> 买家等了二十多分钟，走了。之后 Muse 才回来跟 Matt Robb 道歉。
>
> Matt Robb 最后的提醒是：去看看你给 AI 开了哪些权限。
>
> 再说 Instinct 的设计。
>
> 第一，Instinct 不做 App。你平时怎么发短信、打电话，就怎么找它。Instinct 有自己的手机号、邮箱和电脑，用这些去办事。
>
> 第二，Instinct 只在真着急的时候主动找你。创始人说，几个月里，Instinct 只给他打过大约三次电话。
>
> 第三，Instinct 外面另有一套独立的系统，盯着 Instinct 的每一步，必要时直接拦下来。Instinct 也只和你信得过的人的 agent 打交道。

### run-b

> 我自己用的是 Grok Bot。Grok Bot 也有一台自己的电脑。跑步这边，Grok Bot 帮我做了两件事。
>
> 第一件是调 HUD。HUD 就是视频里叠在画面上的那套跑步数据。
>
> 字体、标签、对齐、进度圈，一个下午改了十几轮。每一轮，Grok Bot 在它自己的电脑上渲一张截图给我看。我说哪里不对，Grok Bot 再改。
>
> Grok Bot 干活，我只管看、只管挑。
>
> 第二件是对字幕。上一期发出去之后，Grok Bot 发现有几条字幕切得不好，想把已经发布的字幕也改掉。
>
> 我拦住了。已经发出去的字幕不回改，只把规则改好，下一期照新规则来。
>
> 我还要求，规则要写成通用的，不能只为某一期单独改。
>
> 规则我来定，Grok Bot 照着做。

### run-c

> 工作上，我有一个专门管 bug 的 agent。
>
> 工作日每 20 分钟，管 bug 的 agent 扫一遍分给我的 bug。后端的 bug，交给开发机上另一个 agent 去修。前端的 bug，转给前端同事。
>
> 两天里，合了 5 个合并请求，打了 6 次镜像。
>
> 但合不合并、发给测试的说明怎么写，每一步都要我点头。
>
> 有一次，两个监控页面上的 CPU 使用率对不上。一个页面大约 58%，另一个大约 29%。
>
> 第一次修反了。把对的那个页面，改成了跟错的那个一样。
>
> 我说，要有足够的证据再改。
>
> 管 bug 的 agent 去查了原始公式。开发机上的 agent 又在测试环境实测。证明是另一个页面算平均值的时候，把一个几乎不占 CPU 的占位容器也算了进去，数字被拉低了一半。
>
> 证据够了，再改回来。
